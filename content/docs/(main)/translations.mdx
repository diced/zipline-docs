## Choosing a language

Zipline uses your browser's preferred language by default. You can change it using the language button in the dashboard header or on the login and public pages. Your choice is saved in your browser.

If a language or translation is unavailable, Zipline falls back to English. API errors and custom text set by an administrator are not translated.

## Contributing

Zipline uses [Weblate](https://wl.diced.sh) for translation contributions. You can help translate missing text or improve existing translations directly in your browser:

1. Open [Zipline's Weblate](https://wl.diced.sh).
2. Sign in with your GitHub account.
3. Choose your language and start translating.

Keep placeholders such as `{{name}}` and tags such as `<anchor>...</anchor>` unchanged. You can move them within the sentence and translate the text between tags.

## Working with translation files

For development or local changes, translation files are in [`src/lib/i18n/locales`](https://github.com/diced/zipline/tree/trunk/src/lib/i18n/locales), organized by language and section of the interface:

```text
src/lib/i18n/locales/en/auth.json
src/lib/i18n/locales/fr/auth.json
```

For example, `auth.json` contains login and registration text, while `common.json` contains shared labels.

### Editing a translation

Edit the file in your language's directory, using the matching English file in `locales/en/` as a reference. Keep the same JSON keys and structure, and translate the values. Missing keys can be added as you translate them; partial translations are supported.

Keep placeholders such as `{{name}}` and tags such as `<anchor>...</anchor>` unchanged. You can move them within the sentence and translate the text between tags.

<Callout type='warning'>
  Do not leave empty values. Omit untranslated keys so Zipline can use the English text instead.
</Callout>

### Plurals

Plural keys use suffixes such as `_one`, `_few`, `_many`, and `_other`. Include every form your language requires; the forms may differ from English.

Use the English `_other` entry as a reference for additional forms. `{{count}}` inserts the number into the sentence.

## Adding a language

To add a language:

1. Create `src/lib/i18n/locales/<code>/` with translated JSON files, using the English filenames and structure.
2. In `src/lib/i18n/languages.ts`, add the language code and its native name to `LANGUAGE_NAMES`. `LANGUAGES` is derived from this map.
3. If the Day.js locale differs from the language code, add a mapping to `DAYJS_OVERRIDES` in the same file.
4. Import the corresponding Day.js locale in `src/lib/i18n/index.ts`.

Language detection currently uses base codes such as `fr` or `pt`. Separate regional variants would also need changes to the detection logic.

## Testing changes locally

Follow the [development setup](/docs/contributing#development), then run:

```bash
pnpm test
pnpm validate
```

The tests check keys, placeholders, tags, empty values, and plural forms. Select your language in Zipline and check the affected pages for text that gets cut off or wraps awkwardly.

If you edit translation files directly, open a pull request against `trunk` with a short description of the language and changes. You can also [report a translation issue](https://github.com/diced/zipline/issues) with the affected page and suggested wording.
