Use OpenID Connect (OIDC) to sign in to Zipline through an identity provider. This guide covers Authentik, Kanidm, Pocket-ID, and Microsoft Entra ID.

## Before you start

The examples use `https://zipline.example.com` for Zipline. Replace it with your instance's public URL.

- Register `https://zipline.example.com/api/auth/oauth/oidc` as the provider's login callback.
- Use a confidential client with a client ID and secret. Zipline requests `openid`, `email`, `profile`, and `offline_access`, and supports PKCE with S256.
- Enable **Server Settings → Features → OAuth Registration** so the login button is available.

Zipline normally builds the callback from the host you access it through. If you need a fixed callback, set **Redirect URL** under **Server Settings → OAuth → OIDC**. It must end in `/api/auth/oauth/oidc` and exactly match the URL registered with your provider.

After completing a provider's setup below, save your Zipline settings and test **Login with OIDC**. To link an existing Zipline account, sign in to it first and link OIDC from your account settings.

## Authentik

### Configure Authentik

1. Open **Applications** in the Authentik admin dashboard and select **Create with Wizard**. If the wizard isn't available, create an application and provider separately.

![authentik create application](/img/docs/oauth-authentik-1.png)

2. Name the application and click **Next**.

![authentik application name](/img/docs/oauth-authentik-2.png)

3. Choose **OAuth2/OIDC (Open Authorization/OpenID Connect)** and click **Next**.

![authentik application type](/img/docs/oauth-authentik-3.png)

4. Name the provider, keep the client type **Confidential**, and choose an authorization flow, such as `default-provider-authorization-explicit-consent`.

![authentik provider name](/img/docs/oauth-authentik-4.png)

5. Copy the **Client ID** and **Client Secret**. Set **Redirect URIs** to `https://zipline.example.com/api/auth/oauth/oidc`.

![authentik redirect uri](/img/docs/oauth-authentik-5.png)

6. Expand **Advanced Protocol Settings** and include the `openid`, `email`, `profile`, and `offline_access` scopes. You may need to hold Ctrl while selecting additional scopes.

![authentik scopes](/img/docs/oauth-authentik-6.png)

7. Submit the application and provider.

### Configure Zipline

Open **Server Settings → OAuth → OIDC** and enter:

| Setting       | Value                                                    |
| ------------- | -------------------------------------------------------- |
| Client ID     | The Authentik client ID                                  |
| Client Secret | The Authentik client secret                              |
| Authorize URL | `https://authentik.example.com/application/o/authorize/` |
| Token URL     | `https://authentik.example.com/application/o/token/`     |
| User Info URL | `https://authentik.example.com/application/o/userinfo/`  |

Replace `authentik.example.com` with your Authentik domain, then save and test the login.

![zipline settings oauth oidc](/img/docs/oauth-authentik-7.png)

## Kanidm

Install the [Kanidm CLI](https://kanidm.github.io/kanidm/stable/client_tools.html) and use your existing Kanidm instance. Replace `https://idm.example.com` with its URL and `ziplineuser1` with an existing username.

### Configure Kanidm

Point the CLI at your instance and sign in as `idm_admin`, or an administrator with permission to manage groups and OAuth2 clients:

```bash
export KANIDM_URL=https://idm.example.com
export KANIDM_NAME=idm_admin
kanidm login
```

Create a group for users who should be able to sign in to Zipline, then add your users:

```bash
kanidm group create zipline_users
kanidm group add-members zipline_users ziplineuser1
```

Create a confidential client, register the callback, and grant Zipline's scopes to the group:

```bash
kanidm system oauth2 create zipline "Zipline" https://zipline.example.com
kanidm system oauth2 add-redirect-url zipline https://zipline.example.com/api/auth/oauth/oidc
kanidm system oauth2 update-scope-map zipline zipline_users openid email profile offline_access
kanidm system oauth2 prefer-short-username zipline
```

The first URL is Zipline's landing page in Kanidm's application portal. The scope map gives members of `zipline_users` access to the client; add more users with `kanidm group add-members`.

`prefer-short-username` makes Kanidm return usernames such as `ziplineuser1` instead of `ziplineuser1@idm.example.com`.

Kanidm enables PKCE by default, and Zipline automatically uses PKCE with S256. No additional setting is needed in Zipline. If PKCE was previously disabled for this client, re-enable it:

```bash
kanidm system oauth2 enable-pkce zipline
```

Keep the client secret configured in Zipline; PKCE works alongside the confidential client's secret.

Retrieve the generated client secret:

```bash
kanidm system oauth2 show-basic-secret zipline
```

### Configure Zipline

In **Server Settings → OAuth → OIDC**, enter:

| Setting       | Value                                                          |
| ------------- | -------------------------------------------------------------- |
| Client ID     | `zipline`                                                      |
| Client Secret | The output of `kanidm system oauth2 show-basic-secret zipline` |
| Authorize URL | `https://idm.example.com/ui/oauth2`                            |
| Token URL     | `https://idm.example.com/oauth2/token`                         |
| User Info URL | `https://idm.example.com/oauth2/openid/zipline/userinfo`       |
| Redirect URL  | `https://zipline.example.com/api/auth/oauth/oidc`              |

You can verify the endpoint URLs using the client-specific discovery document:

```bash
curl --fail --silent --show-error \
  https://idm.example.com/oauth2/openid/zipline/.well-known/openid-configuration
```

Leave **OIDC End Session URL** empty unless the discovery document includes an `end_session_endpoint`. If it does, follow the [OIDC logout setup](#oidc-logout) below.

Save your changes and test **Login with OIDC** as a member of `zipline_users`.

For more details, see [Kanidm's OAuth2 documentation](https://kanidm.github.io/kanidm/stable/integrations/oauth2.html).

## Pocket-ID

### Configure Pocket-ID

Create an OIDC client and register `https://zipline.example.com/api/auth/oauth/oidc` under **Redirect URIs**.

![pocket-id create client](/img/docs/oauth-pocketid-1.png)

### Configure Zipline

Copy these values from Pocket-ID into **Server Settings → OAuth → OIDC**:

| Pocket-ID value   | Zipline setting |
| ----------------- | --------------- |
| Client ID         | Client ID       |
| Client secret     | Client Secret   |
| Authorization URL | Authorize URL   |
| Token URL         | Token URL       |
| Userinfo URL      | User Info URL   |

![pocket-id copy values](/img/docs/oauth-pocketid-2.png)

Save your changes and test the login.

## Microsoft Entra ID

### Configure Microsoft Entra ID

Register an application in the Entra admin center, add `https://zipline.example.com/api/auth/oauth/oidc` as a **Web** redirect URI, and create a client secret under **Certificates & secrets**.

Copy the **Application (client) ID**, client secret value, and **Directory (tenant) ID**. Use the client ID in Zipline's Client ID field; the tenant ID belongs in the endpoint URLs below.

### Configure Zipline

Open **Server Settings → OAuth → OIDC** and enter:

| Setting       | Value                                                                 |
| ------------- | --------------------------------------------------------------------- |
| Client ID     | The Application (client) ID                                           |
| Client Secret | The client secret value                                               |
| Authorize URL | `https://login.microsoftonline.com/<tenant_id>/oauth2/v2.0/authorize` |
| Token URL     | `https://login.microsoftonline.com/<tenant_id>/oauth2/v2.0/token`     |
| User Info URL | `https://graph.microsoft.com/oidc/userinfo`                           |

Replace `<tenant_id>` with your Directory (tenant) ID, then save and test the login.

## OIDC logout

By default, logging out ends your current Zipline session while leaving your OIDC provider session active. Configure the optional **OIDC End Session URL** to also request a logout from your provider when you log out of Zipline.

1. Find your provider's logout endpoint, usually listed as `end_session_endpoint` in its OpenID Connect discovery document.
2. In Zipline, open **Server Settings → OAuth → OIDC**, enter that endpoint in **OIDC End Session URL**, and save your changes.
3. In your provider's client settings, register your Zipline login URL as an allowed post-logout redirect URI, including the query parameter:

```text
https://zipline.example.com/auth/login?logged_out=true
```

Replace `zipline.example.com` with your Zipline domain. If you configured a custom OIDC redirect URL, the logout callback uses the same origin as that URL. Otherwise, it uses the host you accessed Zipline from and the protocol configured by `CORE_RETURN_HTTPS_URLS`.

You can also configure the endpoint through an environment variable:

```dotenv
OAUTH_OIDC_END_SESSION_URL=https://oidc.example.com/logout
```

When you log out of a session created by signing in with OIDC, Zipline ends the local session and redirects your browser to the provider's logout endpoint. The provider can then return you to `/auth/login?logged_out=true`. This query parameter prevents **Bypass Local Login** from immediately sending you back to the provider.

Sessions created with a local login or another OAuth provider only log out of Zipline, even if the account has an OIDC provider linked.

## Other OIDC providers

For another provider, obtain its client credentials, authorization URL, token URL, and userinfo URL from its documentation or discovery document. Apply the callback and scope requirements in [Before you start](#before-you-start).
